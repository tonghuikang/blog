I think it is a good time to understand the different ways your data could be trained on.

[^wikipedia]: There is Wikipedia page on this.

John Schulman [noted](https://x.com/johnschulman2/status/2097440545853637108) that "there are different kinds of training on user data* with very different privacy/IP implications"

> - pretrain on user data, with users' tokens as prediction targets: high regurgitation risk, improper
> - use user prompts to distill large models into small ones: low regurg. risk, some companies probably do this
> - use user traces to construct RL tasks: low regurg. risk, because RL has low memorization abilities, but can extract customer IP, depending on how it's done. Ranges from benign "use explicit user feedback in reward model training" to invasive "upload user's coding environment and commit history to turn into rl envs"

This is how I break down "training on user data".

There are three different aspects on user data.

- Information
- Feedback
- Context

The purpose of this writing is to distiguish between user information, user feedback and user context.


# User information

User information is any information that is not generated by model.

Consider the following conversations

> User: My name is Hui Kang.
> ...
> Assistant: Thanks for the feedback! As a token of appreciation
> User: My phone number is XXX-XXX-XXXX
> Assistant: I assume that you live in the United States. I would like to confirm that your phone number is XXX-XXX-XXXX.
> User: That is correct, and thank you!

LLMs predict the next token given the context.
If you train an LLM to predict "User: My phone number is XXX-XXX-XXXX",
you are training to predict my phone number given my name. [^website]
People using my the models may be able to repeat my phone number.

However, you can train on "I would like to confirm that your phone number is XXX-XXX-XXXX.".
THis is generated by the model, not provided by the user.
I would argue that training on model outputs will not make it more likely to learn my phone number. [^leakage]
The model has context of what my phone number is, and is repeating it. [^redaction]
We want models to be flawless at repeating information.

[^leakage]: I think it is still an open question on whether can you more likely to extract my phone number.
[^redaction]: Ideally, both phone numbers should be replaced before entering the training system.
    However, this may not always work.
    There are user information that are not phone numbers, like addresses.
    Also the user input might be voice, and it defeats the purpose if you replace the user voice with a synthetic voice.
    My argument here is that we should NOT train on user information.

User information does not necessary mean that the user has to be the one providing the information.
Tool output could be considered user input as well.

> Assistant: whoami
> Tool response: huikang
> Assistant: Let me print the SSH key. [^hidden] [bash-start]cat <>[bash-end]
> Tool response: XXXX

[^hidden]: It seems that OpenAI and Anthropic LLMs proactively avoid getting the SSH and API keys into context.

If you train on the SSH key, you are training to predict my SSH key given my user name.

There are many parts of the user conversation that can be derived from the context.
We know that is is possible to predict the user starting with "My phone number is" or the tool use response where the first characters of the SSH key being "AAAAAA".

User information does not necessarily need to be high entropy as well.

I argue that the the benefit on training on user information is very minimal.
You should be training the model to provide a better response.

# User feedback

> User: Please open up puppeteer

AI product should still provide affordances for users to provide feedback.

# User context

The real world is full of tasks.

You cannot really decouple user information from user context.

I think there is a lot of potential in training on user context in a way that is privacy preserving.

For a given trace, you can reroll every step in the user output.

You do not need the environment, you just need the user trace.
Of course, the trace can come from the environment.

The measurement here is whether AI is making the correct action at every step.

You are not reproducing user data as well.
It is possible that the AI needs to repeat the user private information, but the AI is not trained to memorize one.



# Conclusion

I hope AI models do NOT train on user information.

User feedback could be used to identify useful user context that could be used to train the model.
I think there is a lot of potential is using user context, combined with user feedback, to train models.

I believe that training on user context do not hurt user privacy.
The model just gets better at tasks you might be doing.
The model learns the best thing to do given the context.

We would still require user consent though.
The user does not necessary want the model to be better at the job that they do.
